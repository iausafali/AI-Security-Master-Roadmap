## Execution rules

1. Do not add a new course merely because it sounds impressive.
2. Do not remove a canonical resource merely because a project appears to cover similar material.
3. Prefer implementation and experiments over passive course completion.
4. Use problem-first learning: attempt first, learn the missing concept, then reattempt.
5. Security work is restricted to owned, intentionally vulnerable, or explicitly authorized environments.
6. University periods prioritize AI, mathematics, and systems; security remains a deliberate secondary lane.
7. Breaks are used for the current deep-dive specialty.
8. After graduation, AI systems/research and security/research progressively converge.
9. Phase completion requires evidence, not certificates: implementation, testing, benchmarks, security lab records, or research artifacts.
10. The roadmap should be revised only deliberately. Do not let project-level experimentation silently become a new curriculum.

## Public-facing terminology

This repository is intended to be shareable with students, engineers, and researchers. Use professional terms such as **mastery standard**, **verification protocol**, **exit criteria**, **evidence of competence**, and **research milestone** in public documentation.
